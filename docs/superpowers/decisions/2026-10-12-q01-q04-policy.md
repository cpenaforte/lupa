# Q01–Q04 policy decisions

Date: 2026-10-12
Status: decided (roadmap Task 50; feeds the F14 design and later implementations)
Source: Codex audit `PROJECT_FINDINGS.md` Q01–Q04, decided with the owner.
No code changes in this record — behavior questions are settled here first.

## Q01 — suggestion fences require a validated replacement patch

Decision: only an explicitly marked replacement patch renders as an applicable
GitHub suggestion fence. Everything else — explanatory prose, unmarked or
malformed suggestions — renders as advice text. Automatic application stays
out of scope.

Strictness is conditional: the strict marker applies only if the LLM can emit
it as structured output exclusive to patches (typed field or tool call).
Feasibility is verified during F14 design against provider capabilities. If
structured patch output is not available, the fallback is target+range-only
validation (valid RIGHT-side line target renders fenced; invalid targets
render as advice).

## Q02 — only new/worsened findings block; wrongly resolved blocks may reopen

Decision: PR-introduced or worsened findings block. Pre-existing baseline
findings stay visible with provenance but never block on their own.

Reopen exception: a past block may re-arm — and block again — only if it was
wrongly resolved, i.e. a user clicked Resolve conversation on a workflow
review thread (treating the finding as a false positive or done) while the
flagged issue still needs a fix. The workflow must therefore read the
resolution state of its own review threads and re-check resolved findings
against the current code: issue persists → re-raise as blocking; issue
gone → stays resolved. No persistence check, no reopen.

## Q03 — weakest heuristic signals are dropped, not emitted

Decision: no findings are emitted for deletions, public certificates,
placeholders, or unchanged TODO context lines. Heuristic-only findings without
direct secret evidence must not exist as findings at all (neither high nor
downgraded) — the false-positive cost exceeds their value. What counts as
public material vs a real secret introduction is defined at implementation
time.

## Q04 — severity blocking stays; provenance and confidence are recorded

Decision: any high-severity finding blocks, including LLM-only highs — the
model's high judgment is trusted. This overrules the audit's corroboration
direction deliberately. No deterministic-corroboration gate is added.

Findings gain structured provenance and a confidence level in the finding
contract JSON (display and future calibration). Confidence never overrides
severity for blocking today.

## Unresolved tradeoffs (for F14 design and later)

- Q01: structured-patch-output feasibility per provider (typed field vs tool
  call); exact marker format and prose-vs-patch fallback wording.
- Q02: precise re-check rules (finding-identity matching across runs,
  thread-resolution read scope, staleness bounds for resolved threads).
- Q03: detection rules separating public material/placeholders from real
  secret introductions.
- Q04: confidence scale and thresholds (display-only initially).
