# Q02 novelty-gated blocking Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Only PR-touched findings (plus wrongly-resolved reopened ones) block; everything else stays visible and never gates.

**Architecture:** Task 72 partitions the merged set into introduced vs general on touched-line + file-membership rules, swaps all three gate call sites to the blocking set, and marks every non-blocking body/fold item. Task 73 adds the GraphQL thread re-read with pure matching and promotes persisting resolved findings. Sequential (72 → 73). (Third follow-up of the dedup → Q04 → Q02 → Q01 order.)

**Tech Stack:** TypeScript 5.x, Node >=24, vitest, esbuild (`dist/` committed), `octokit.graphql` (bundled in `@actions/github`, no new dep).

**Spec:** `docs/superpowers/specs/2026-10-12-q02-blocking-design.md`

## Global Constraints

- No new runtime dependencies, no new action inputs, no template or CI changes.
- `PR_REVIEWER_*` env names, `pr-reviewer-*` strings, `pr-reviewer/1.0` user-agent, SARIF driver name, `lupa:` log prefixes unchanged.
- Every task ends with `npx tsc --noEmit -p tsconfig.json`, `npm run build && node --check dist/index.js` and commits `dist/index.js`.
- Full suite (`npx vitest run`) + evals (`npm run evals`) green before every task commit (evals after build).
- Commit messages use the exact strings given per task.
- Task 73 merges only on a passing live canary (spec §5) — no pass, no merge.
- Ships with the next release vehicle — no tag alone.

## Review Focus

- **A high on an unchanged context line of a touched file stays inline but doesn't block.** Test in Task 72's step style (ctx-line high → COMMENT + exit 0, still in body).
- **An added empty `.env` (no hunks) still blocks via the file set.** Test in Task 72's step style (hunks-"" file membership → REQUEST_CHANGES + exit 1).
- **A resolved thread whose line drifted to context re-blocks with an inline marker while the issue persists.** Test in Task 73's step style.
- **A `ruleA+ruleB` thread reopens unmerged `ruleA`/`ruleB` findings at the same spot.** Test in Task 73's step style (intersection match).
- **A 422 off-diff retry keeps `(non-blocking)` fold markers.** Test in Task 72's step style (commentKeys threading).

**Files:**

- Rebuild: `dist/index.js`

**Interfaces:**
- Consumes: merged finding set + `FileDiff[]` (`a.hunks`, has `.file`) + parsed hunks (existing `publishReview` locals).
- Produces: `partitionGate(findings, hunks, files): { introduced, general }`; `reopenedKey(f): string` (`rule\0file\0line`); `indexHunks(hunks)`; `buildBody(general, summary, marks?: { reopened?, blocking? })`; `publishReview(...): Promise<{ blocking: Finding[] }>` (reopened empty in this task — no thread read yet).

**Exact behavior:**
- `introduced` = RIGHT-hit with `kind === "add"` (ctx + LEFT display-inline but never gate) + lineless with file in the FileDiff set (binary/mode-only/rename with `hunks === ""` included; deletions included; `file: ""` never). `mapToComments` refactored onto shared `indexHunks` + hit helper, display byte-identical.
- Gates: `eventFor(failLevel, blocking)`, both exits `exitFor(failLevel, blocking)`; computed BEFORE dry-run/fork-readonly/stale-head returns. Dry-run log keeps full-set `high` count, gains `blocking=<n>`.
- Body: header note `${head}\n\n**Note:** <n> finding(s) below are outside the PR diff and do not block.\n\n**Findings not placed inline:**\nitems` (`n` = items outside blocking; omitted when zero); item markers `**reopened**` (reopened wins) else `**blocking**` after severity. Folds: `- path:line (non-blocking)` for keys outside blocking at both sites.
- Payload: `comments: postedInline.map(({ rule, ...c }) => c)` (shape unchanged — no bundle pin updates); `commentKeys` (null where rule absent) + `blocking` in createReview opts (fakes ignore them).
- README gate docs per spec §5 (reopen docs stay in Task 73).

### Task 73: Q02 — wrongly-resolved reopen check

**Files:**
- Modify: `src/review.ts` (`normalizeBot`, `resolveReopened`, `mapToComments` reopened param, `formatBody` marker), `src/github.ts` (`ReviewThread`, `listReviewThreads` via `octokit.graphql`), `src/main.ts` (`Gateway` +2 methods, realGateway impl with `context.repo` + token-entry skip, `publishReview` wiring + short-circuit, createReview opts pass-through), `README.md` (reopen documentation)
- Test: `tests/review.test.ts` (match units + all negations), `tests/github.test.ts` (fetch units with mocked graphql), `tests/main.test.ts` (`gatewayFor`) + `tests/evals/harness.ts` gateway fake (+2 methods), gate reopen pins, inline `**reopened**` pin
- Rebuild: `dist/index.js`
- Live canary on test-lupa (merge gate — evidence in task report, no pass = no merge)

**Interfaces:**
- Consumes: Task 72's `partitionGate`/`reopenedKey`/`buildBody` marks/`publishReview` return/`commentKeys` threading.
- Produces: `resolveReopened(findings, threads, selfLogin): Set<string>` (over merged, any position); `normalizeBot(login): string`; reopened keys flow into blocking + marks + inline marker. Nothing downstream (terminal task).

**Exact behavior:**
- Match: keep thread iff `isResolved && normalizeBot(author) === normalizeBot(self) && rule !== null` (null author never); rule INTERSECTION (`split("+")` both sides, non-empty); file exact; thread line `line ?? originalLine` (both absent → no match). `blocking = introduced + merged.filter(key ∈ reopened)`, order preserved.
- Fetch: `reviewThreads(last:100)` + listed fields + `pageInfo { hasPreviousPage }`; rule via `/^\*\*(\w+)\*\* \[(.+?)\]/` on first-comment body (fail-safe null); `hasPreviousPage` → `lupa:` warn + use 100; any error → warn + empty; empty token → empty at entry (no call, no warn). Self via `users.getAuthenticated` (same token); failure → undefined → warn + skip.
- Wiring: short-circuit both calls iff every merged finding is introduced; thread read inside `publishReview` pre-early-returns; inline reopened items via `formatBody(f, side, true)` through `mapToComments(findings, hunks, reopened)`.
- README reopen section per spec §5.

- [ ] **Step 1: Write the failing tests**
  - `resolveReopened`: positive (resolved + self + rule + exact file/line; `originalLine`-only; joined-thread vs unmerged members; drifted-line member) + every negation (unresolved, foreign author, null author, null rule, `]`-in-rule, line mismatch, both-lines-absent).
  - `normalizeBot` both-sides (`x[bot]` ≡ `x`, plain unchanged).
  - Fetch: newest-100, hasPreviousPage warn, error → empty, unparseable → null, token-empty → no call.
  - Gates: persists → re-blocks with marker (body AND inline-drift cases); gone → resolved; API failure → diff-only; all-introduced → `getActor`/`listReviewThreads` never called.
  - Fakes carry the new methods (defaults: no threads, actor set).
