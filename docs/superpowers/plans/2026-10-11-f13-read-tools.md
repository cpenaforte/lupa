# F13 read-tool coverage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the agent read tools report honestly — pure path discovery in `glob`, visible-range line metadata in `read_file`, and bounded traversal with explicit skip counts.

**Architecture:** Split the shared walk into a names-only path walk and the existing content walk (both bounded, both pruned); surface skip counts through the grep response; recompute `read_file`'s `end_line` from the visible cut. Two tasks: walks/glob/grep first, then the independent `read_file` fix.

**Tech Stack:** TypeScript 5.x, Node >=24, vitest, esbuild (`dist/` committed).

**Spec:** `docs/superpowers/specs/2026-10-11-f13-read-tools-design.md`

## Review Focus

- **A >1 MiB source file and a binary file must appear in `glob` results** (pure discovery) while staying out of `grep` content with counted skips. Test in Task 54's step style.
- **A truncated `read_file` must never claim an unseen line**, including when the byte cut lands exactly on a `\n` boundary. Test in Task 55's step style.
- **A walk that hits `maxFiles` must stop and say so** (`truncated: true`, `overLimit > 0`). Test in Task 54's step style.
- **Pruned subtrees (`node_modules/`, `vendor/`) must not appear in `glob` or `grep`** while sibling source does. Test in Task 54's step style.
- **`files_scanned` keeps meaning files the worker read** (not walk-visited). Pinned by existing tests, unchanged.

### Task 54: F13 — pure glob, bounded walks, grep skip counts

**Files:**
- Modify: `src/agent-tools.ts` (`WalkLimits`, `WalkSkipped`, `walkPaths`, `walkFiles` return shape, `glob`, `grepInRoot` response)
- Test: `tests/agent-tools.test.ts`

**Interfaces:**
- Consumes: `matchGlob`, `GLOB_MAX_PATHS`, `GREP_MAX_FILE_BYTES`, `AGENT_LIMITS.resultBytes` (existing, unchanged).
- Produces: `export interface WalkLimits { maxFiles?: number; deadlineMs?: number }` (defaults 10_000 / 10_000); `export interface WalkSkipped { oversized: number; binary: number; overLimit: number }` where `overLimit` counts only limit-cut entries still queued at fire time (pruned/`.git`/symlink entries are deliberately skipped, never limit-cut; 0 unless a limit fired). Unreadable files fold into `binary` (the reused eligibility check treats open failure as binary); walks return `{ files|paths, truncated, skipped }`; grep response gains `skipped: WalkSkipped`.
- Testability seam (required): `walkFiles` and `walkPaths` are exported as `walkFiles(root: string, startAbs: string, limits?: WalkLimits)` / `walkPaths(root: string, startAbs: string, limits?: WalkLimits)` (same parameter order as today plus trailing optional limits), so the limit tests drive them directly. `grepInRoot` keeps its signature.

**Exact behavior:**
- Prune set (`node_modules`, `vendor`, `target`, `.venv`, `venv`, `__pycache__`): exact entry-name match, any depth, file or directory; `.git` keeps its case-insensitive entry check; symlinks skipped; non-regular nodes skipped. Applies to both walks.
- `dist/` and `build/` are explicitly NOT pruned (project outputs, sometimes reviewed).
- `walkPaths`: no stat/binary checks; `{paths (rel, sorted), truncated, skipped}` with `oversized`/`binary` 0 and `overLimit` = queue remainder at limit fire (0 otherwise). `glob` filters by pattern, caps 200, `truncated` = cap-hit OR walk-limit-hit. Shape `{paths, truncated}` unchanged.
- `walkFiles`: same walk + eligibility (size, binary); real `skipped` counts; `maxFiles` counts examined files; deadline checked per directory (documented one-directory overshoot granularity in a comment).
- `grepInRoot`: `truncated` = hitLimit OR byte-cap cut OR walk-limit-hit; response `{matches, truncated, files_scanned, skipped}`.

### Task 55: F13 — truthful read_file end_line

**Files:**
- Modify: `src/agent-tools.ts` (`readFile` end_line computation only)
- Test: `tests/agent-tools.test.ts`

**Interfaces:**
- Consumes: nothing from Task 54 (independent code path; order is conventional).
- Produces: `end_line` always equals the last visible numbered line.

**Exact behavior:**
- After the byte-budget cut: `parts = cut.split("\n"); visibleLines = cut === "" ? 0 : parts.length - (parts[parts.length - 1] === "" ? 1 : 0)` over the cut portion only (marker excluded); `end_line = visibleLines ? start + visibleLines - 1 : start - 1`. Untruncated path unchanged.
