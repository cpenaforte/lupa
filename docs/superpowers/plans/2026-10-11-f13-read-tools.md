# F13 read-tool coverage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the agent read tools report honestly — pure path discovery in `glob`, visible-range line metadata in `read_file`, and bounded traversal with explicit skip counts.

**Architecture:** Split the shared walk into a names-only path walk and the existing content walk (both bounded, both pruned); surface skip counts through the grep response; recompute `read_file`'s `end_line` from the visible cut. Two tasks: walks/glob/grep first, then the independent `read_file` fix.

**Tech Stack:** TypeScript 5.x, Node >=24, vitest, esbuild (`dist/` committed).

**Spec:** `docs/superpowers/specs/2026-10-11-f13-read-tools-design.md`

## Review Focus

- **A >1 MiB source file and a binary file must appear in `glob` results** (pure discovery) while staying out of `grep` content with counted skips. Test in Task 54's step style.
- **A truncated `read_file` must never claim an unseen line.** Partial tails are backed up (no complete line visible → `end_line = start - 1`). Test in Task 55's step style.
- **A walk that hits `maxFiles` must stop and say so** (`truncated: true`, `overLimit > 0`). Test in Task 54's step style.
- **Pruned subtrees (`node_modules/`, `vendor/`) must not appear in `glob` or `grep`** while sibling source does. Test in Task 54's step style.
- **`files_scanned` keeps meaning files the worker attempted** (not walk-visited; the counter increments before the read). Existing tests assert it is positive; the new Task 54 tests pin exact values.

### Task 54: F13 — pure glob, bounded walks, grep skip counts

**Files:**
- Modify: `src/agent-tools.ts` (`WalkLimits`, `WalkSkipped`, `walkPaths`, `walkFiles` return shape, `glob`, `grepInRoot` response)
- Test: `tests/agent-tools.test.ts`

**Interfaces:**
- Consumes: `matchGlob`, `GLOB_MAX_PATHS`, `GREP_MAX_FILE_BYTES`, `AGENT_LIMITS.resultBytes` (existing, unchanged).
- Produces: `export interface WalkLimits { maxFiles?: number; deadlineMs?: number }` (defaults 10_000 / 10_000); `export interface WalkSkipped { oversized: number; binary: number; overLimit: number }` where `overLimit` counts only limit-cut entries still queued at fire time (pruned/`.git`/symlink/non-regular entries are deliberately skipped, never limit-cut; 0 unless a limit fired — a limit fires only when an unexamined entry remains, so exact fit yields `truncated: false`). Unreadable files fold into `binary` (the reused eligibility check treats open failure as binary); walks return `{ files|paths, truncated, skipped }`; grep response gains `skipped: WalkSkipped`.
- Testability seam (required): `walkFiles` and `walkPaths` are exported as `walkFiles(root: string, startAbs: string, limits?: WalkLimits)` / `walkPaths(root: string, startAbs: string, limits?: WalkLimits)` (same parameter order as today plus trailing optional limits), so the limit tests drive them directly. `grepInRoot` gains an optional trailing `limits?: WalkLimits` (4th param, backward compatible) threaded to its internal walk, so the grep walk-limit path is testable without a 10k-file fixture.
- `maxFiles` counts entries examined: each dirent classified in a directory loop counts 1 (files and directories alike; pruned/`.git`/symlink/non-regular entries are never examined and never counted). `overLimit` = remainder of the current directory loop + 1 per stacked unvisited directory (directory contents are unknowable without visiting — counted as one unit each, stated explicitly). `statSync`-failure skips count in no bucket.

**Exact behavior:**
- Prune set (`node_modules`, `vendor`, `target`, `.venv`, `venv`, `__pycache__`): exact entry-name match, any depth, file or directory; `.git` keeps its case-insensitive entry check; symlinks skipped; non-regular nodes skipped. Applies to child entries under the walk start; the start path itself is never pruned (`path: "vendor"` still searches). Applies to both walks.
- `dist/` and `build/` are explicitly NOT pruned (project outputs, sometimes reviewed).
- `walkPaths`: no stat/binary checks; `{paths (rel, sorted), truncated, skipped}` with `oversized`/`binary` 0 and `overLimit` = queue remainder at limit fire (0 otherwise; the remainder count excludes pruned/`.git`/symlink entries — filter those before counting). `glob` filters by pattern, caps 200, `truncated` = cap-hit OR walk-limit-hit. Shape `{paths, truncated}` unchanged.
- `walkFiles`: same walk + eligibility (size, binary); real `skipped` counts; `maxFiles` counts entries examined (as above); deadline checked per directory (documented one-directory overshoot granularity in a comment).
- `grepInRoot`: `truncated` = hitLimit OR byte-cap cut OR walk-limit-hit; response `{matches, truncated, files_scanned, skipped}`. Skip counts describe the walk (pre-glob-filter) by intent: the `glob` argument filters after the walk, so `skipped` may count files the pattern would not have matched.

### Task 55: F13 — truthful read_file end_line

**Files:**
- Modify: `src/agent-tools.ts` (`readFile` end_line computation only)
- Test: `tests/agent-tools.test.ts`

**Interfaces:**
- Consumes: nothing from Task 54 (independent code path; order is conventional).
- Produces: `end_line` always equals the last visible numbered line.

**Exact behavior:**
- After the byte-budget cut, back up to the last `\n` (`idx = cut.lastIndexOf("\n"); visible = idx < 0 ? "" : cut.slice(0, idx)`); when the cut contains no `\n` (a single line exceeds the whole budget), `visible` is empty and `end_line = start - 1` (no complete line is visible; resuming at `start` re-reads, never skips — same convention as the existing `actualEnd`). Otherwise `visibleLines = visible.split("\n").length` and `end_line = start + visibleLines - 1`, counted over the backed-up portion only (marker excluded). Untruncated path unchanged.
