# F13 read-tool coverage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the agent read tools report honestly — pure path discovery in `glob`, visible-range line metadata in `read_file`, and bounded traversal with explicit skip counts.

**Architecture:** Split the shared walk into a names-only path walk and the existing content walk (both bounded, both pruned); surface skip counts through the grep response; recompute `read_file`'s `end_line` from the visible cut. Two tasks: walks/glob/grep first, then the independent `read_file` fix.

**Tech Stack:** TypeScript 5.x, Node >=24, vitest, esbuild (`dist/` committed).

**Spec:** `docs/superpowers/specs/2026-10-11-f13-read-tools-design.md`

## Global Constraints

- No new runtime dependencies (node builtins + existing deps only). No new action inputs. `PR_REVIEWER_*` env names, `pr-reviewer-*` concurrency/artifact strings, `pr-reviewer/1.0` user-agent, SARIF driver name, and `lupa:` log prefixes stay unchanged.
- Every task ends with `npx tsc --noEmit -p tsconfig.json`, `npm run build && node --check dist/index.js` and commits `dist/index.js`.
- Full suite (`npx vitest run`) green before every task commit; no test deleted without a replacement asserting the new contract.
- Commit messages use the exact strings given per task.
- Ships with the whole-plan release — no tag for F13 alone.
- F11 coordination is interface-only: the `limits` parameter is the seam F11's whole-review deadline will later plug into; this plan changes no F11 behavior and moves no deadline.

## Review Focus

- **A >1 MiB source file and a binary file must appear in `glob` results** (pure discovery) while staying out of `grep` content with counted skips. Test in Task 54's step style.
- **A truncated `read_file` must never claim an unseen line.** Partial tails are backed up; the single-line fallback shows the partial with `end_line = start - 1`. Test in Task 55's step style.
- **A walk that hits `maxFiles` must stop and say so** (`truncated: true`; `overLimit` exact for loop remainders, placeholder for unlisted directories — see counting rules). Test in Task 54's step style.
- **A remainder consisting only of pruned/`.git`/symlink/non-regular entries never fires a limit** (`truncated: false`, `overLimit: 0`) — only genuinely unexamined entries count. Test in Task 54's step style.
- **Pruned subtrees (`node_modules/`, `vendor/`) must not appear in `glob` or `grep`** while sibling source does. Test in Task 54's step style.
- **`files_scanned` keeps meaning files the worker attempted** (not walk-visited; the counter increments before the read). Existing tests assert it is positive; the new Task 54 tests pin exact values.

### Task 54: F13 — pure glob, bounded walks, grep skip counts

**Files:**
- Modify: `src/agent-tools.ts` (`WalkLimits`, `WalkSkipped`, `walkPaths`, `walkFiles` return shape, `glob`, `grepInRoot` response)
- Test: `tests/agent-tools.test.ts`

**Interfaces:**
- Consumes: `matchGlob`, `GLOB_MAX_PATHS`, `GREP_MAX_FILE_BYTES`, `AGENT_LIMITS.resultBytes` (existing, unchanged).
- Produces: `export interface WalkLimits { maxFiles?: number; deadlineMs?: number }` (defaults 10_000 / 10_000); `export interface WalkSkipped { oversized: number; binary: number; overLimit: number }` where `overLimit` counts only limit-cut entries still queued at fire time (pruned/`.git`/symlink/non-regular entries are deliberately skipped, never limit-cut; 0 unless a limit fired — a limit fires only when an unexamined entry remains, so exact fit yields `truncated: false`). Unreadable files fold into `binary` (the reused eligibility check treats open failure as binary); walks return `{ files|paths, truncated, skipped }`; grep response gains `skipped: WalkSkipped`.
- Testability seam (required): `walkFiles` and `walkPaths` are exported as `walkFiles(root: string, startAbs: string, limits?: WalkLimits)` / `walkPaths(root: string, startAbs: string, limits?: WalkLimits)` (same parameter order as today plus trailing optional limits; both honor `maxFiles`/`deadlineMs`, so `glob` inherits the default 10 s bound), so the limit tests drive them directly. `isBinaryFile` is exported for the unreadable-fold unit test. `grepInRoot` gains an optional trailing `limits?: WalkLimits` (4th param, backward compatible) threaded to its internal walk, so the grep walk-limit path is testable without a 10k-file fixture. A file start path counts as one examined unit for `maxFiles`.
- `maxFiles` counts entries examined: each dirent classified in a directory loop counts 1 (files and directories alike). The prune filter runs BEFORE the limit check: pruned/`.git`/symlink/non-regular entries are skipped without touching the counter (so a root holding only `node_modules/` with `maxFiles: 1` yields `truncated: false`, `overLimit: 0` — pinned by test). The limit is checked in two places: (a) before classifying each entry (`examinedCount >= maxFiles` → stop); (b) at the top of each loop iteration after pop, before readdir (covers directories pushed when the count is already at max — the loop is `while (stack.length)`, so a pushed-but-unlisted directory is popped and the check fires there; this is what makes the end-of-walk case reachable by construction). At any stop, `overLimit` = unprocessed entries in the current loop (for (a)) + 1 for the current directory when its listing was never read (for (b)) + 1 per remaining stacked directory. `overLimit` is exact for loop remainders and a conservative placeholder (one unit per unlisted directory) when (b) fires — stated explicitly, not silently exact. A limit fires only when an unexamined entry remains (exact fit with an empty stack yields `truncated: false`); `maxFiles: 0` fires on any entry (test-seam use). `statSync`- and `readdirSync`-failure skips count in no bucket. Directory entries are processed in `readdirSync` order (filesystem-dependent); every limit test below uses fixtures whose verdict holds under any order.
- Deadline: `elapsed >= deadlineMs` against `Date.now()`, checked at the top of each directory iteration including the first, at the same point as check (b) above (so `deadlineMs: 0` fires deterministically with the unvisited start directory as its one queued unit). The deadline never applies to a file start (no directory iteration — file-start eligibility only).

**Exact behavior:**
- Prune set (`node_modules`, `vendor`, `target`, `.venv`, `venv`, `__pycache__`): exact DIRECTORY entry-name match, any depth; `.git` keeps its case-insensitive entry check; symlinks skipped; non-regular nodes skipped. Only directories are pruned — a file with a prune-set name is listed/checked normally (dependencies are directories; dropping a named file silently would be F13 concealment). Applies to child entries under the walk start; the start path itself is never pruned (`path: "vendor"` still searches). Applies to both walks.
- `dist/` and `build/` are explicitly NOT pruned (project outputs, sometimes reviewed).
- `walkPaths`: no stat/binary checks; `{paths (rel, sorted), truncated, skipped}` with `oversized`/`binary` 0 and `overLimit` = queue remainder at limit fire per the counting rules above (0 otherwise; the exact/placeholder distinction applies as stated there). `glob` filters by pattern, caps 200, `truncated` = cap-hit OR walk-limit-hit. Shape `{paths, truncated}` unchanged.
- `walkFiles`: same walk + eligibility (size, binary); real `skipped` counts; `maxFiles` counts entries examined (as above); deadline checked per directory (documented one-directory overshoot granularity in a comment).
- `grepInRoot`: `truncated` = hitLimit OR byte-cap cut OR walk-limit-hit; response `{matches, truncated, files_scanned, skipped}`. Both byte-budget `serialize` calls (probe + final) include the fixed `skipped` object so the final response stays within `AGENT_LIMITS.resultBytes`. Skip counts describe the walk (pre-glob-filter) by intent: the `glob` argument filters after the walk, so `skipped` may count files the pattern would not have matched.

### Task 55: F13 — truthful read_file end_line

**Files:**
- Modify: `src/agent-tools.ts` (`readFile` end_line computation only)
- Test: `tests/agent-tools.test.ts`

**Interfaces:**
- Consumes: nothing from Task 54 (independent code path; order is conventional).
- Produces: `end_line` always equals the last fully visible numbered line (`start - 1` when none is fully visible).

**Exact behavior:**
- After the byte-budget cut, back up to the last `\n` (`idx = cut.lastIndexOf("\n"); complete = idx >= 0; visible = complete ? cut.slice(0, idx) : cut` — the partial line stays visible); `end_line = complete ? start + visible.split("\n").length - 1 : start - 1` (no complete line visible → resume re-reads, never skips — same convention as the existing `actualEnd`). Untruncated path unchanged.
